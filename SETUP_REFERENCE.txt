HOW THE LIVE REQUEST WORKS
The client reads bounded evidence, requests a GitHub OIDC identity with the
course origin as audience, and POSTs {"input":"..."} to origin/review using
that identity as Bearer authorization. Successful JSON has text and model.
The OpenAI credential stays in the instructor's gateway. Students do not use
an OpenAI SDK, ChatGPT subscription, Cloud Run account, or Google credentials.
The report job alone needs contents: read and id-token: write permissions.
Live mode runs inside authorized Actions; locally use --offline-demo or mocks.
One request, no retry loop. Max input 12,000 characters; output capped at 450
model tokens. Develop using mocks; 20 requests/UTC day and 500 total per team
through Jan 1, 2027. Expiry Jan 2 midnight Mountain. Failures after reservation
can consume allowance. These limits do not limit ordinary CI or Render builds.

TROUBLESHOOT WITHOUT REPEATED LIVE CALLS
- Missing file/commit mismatch: inspect quality-evidence artifact and collector
  paths; keep collect and report on the same github.sha. Do not reuse latest
  artifacts from another run. Inspect failed evidence job before skipped report.
- Missing OIDC environment variables locally: expected; use offline mode.
  In Actions check id-token: write on report job and organization restrictions.
- 400/413: nonempty JSON input string only; reduce bounded excerpts below limit.
- 401: fresh OIDC token, correct audience, Bearer header; never log the token.
- 403: verify groupN-fall2026, main, push event, quality.yml path, expiry,
  and no environment declaration changing the identity subject.
- 409: identity already used; no repeated request with the same token.
- 429: shared team allowance; wait for next UTC day for daily cap. Lifetime cap
  does not reset daily. Coordinate calls with teammates; do not loop retries.
- 502/503 or timeout: preserve failure artifact. Verify local mocks and input,
  then report persistent service trouble; do not repeatedly consume allowance.
- Empty/invalid JSON/text: retain unavailable report; fail job; test this case.
- Report missing: inspect generate step and always-run upload; output path must
  match upload. Artifacts are not source commits; download before retention ends.
- Render fails: inspect build/start logs. Check root, dependency versions, WSGI
  module, PORT binding, allowed host, database and migrations. HTTP 400 often
  means host configuration; form CSRF errors require correct trusted origin.
  DEBUG must be parsed as a boolean, not bool('False'), which is True in Python.
- Use Neon Free PostgreSQL with Render Free for the app through January 1, 2027.
  Follow the course's exact setup, migration, persistence and usage instructions:
  https://docs.google.com/document/d/1kFwsMl1WJQqpgnCJZnlUDi_aafPUirSBpkRgkVCsAoI/edit
  Do not create Render's 30-day Postgres trial. Neon has no current trial expiry,
  but free usage quotas apply. Keep CI on a disposable database. Local uploads
  on Render remain ephemeral even when database rows persist in Neon.
